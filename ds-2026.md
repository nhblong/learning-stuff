### 1. Hash-based structures

| Structure | Short description | Example application/demo |
|---|---|---|
| Hash table with separate chaining | Stores colliding entries in a collection attached to each bucket. | Store student IDs; insert two IDs with the same hash and display their bucket list. |
| Hash table with linear probing | Resolves collisions by checking consecutive slots. | Insert colliding IDs and show how they occupy neighboring slots. |
| Hash table with quadratic probing | Resolves collisions using quadratic probe offsets. | Trace the slots checked when several keys share a hash value. |
| Hash table with double hashing | Uses a second hash function to determine the probing step. | Compare the probe sequences of two colliding keys. |
| Robin Hood hash table | Balances probe distances by relocating entries during insertion. | Insert keys and display which entry gives up its slot to a more displaced key. |
| Cuckoo hash table | Gives each key candidate locations and relocates entries when necessary. | Animate a new key displacing existing keys between two tables. |
| Extendible hash table | Uses a growing directory pointing to buckets. | Insert records until a bucket splits; show the directory before and after. |
| Linear hashing | Expands incrementally by splitting buckets. | Insert records and track the next bucket selected for splitting. |
| Perfect / minimal perfect hash structure | Maps a fixed key set without collisions; minimal uses exactly one slot per key. | Build collision-free lookup for a fixed list of course codes. |
| Hopscotch hash table | Keeps entries within a neighborhood of their original buckets. | Show entries moving to create a nearby slot for a new key. |
| Distributed hash table (DHT) | Distributes key ownership and lookup across networked nodes. | Simulate four computers storing and locating files by hashed names. |
